RAG-Suche: pro Nutzerfrage

Die Frage wird gegen Keywords und bei Bedarf semantisch gesucht.

01 · SUCHE 1

Keyword-Treffer

  • Stopwörter filtern
  • exakte Begriffe und Token bewerten
02 · SUCHE 2

FAISS-Fallback

  • nur ohne Keyword-Treffer
  • Top 3 ab Mindestscore 0,75
03 · BELEG

Kontext übergeben

  • Treffertexte als Antwortkontext
  • Dokument-ID und Titel sichtbar halten

05 · Sicherheitsmechanismen

Regeln: prüfen statt raten

1 Systemprompt setzt Leitplanken

Die Grundregeln stehen vor jeder Nutzerfrage fest: Rolle, Themenbereich und Quellenpflicht. 

SYSTEM:
  nur GKV-Kontext
  Quellen nennen
  nichts erfinden

Nutzer darf diese
Regeln nicht ändern
2 Erst fragen: passt das Thema?

Der Agent beantwortet nur GKV-Fragen aus freigegebenem Wissen. Alles andere wird klar abgegrenzt. 

GKV_THEMEN = [
  Krankengeld, PZR,
  Belastungsgrenze, ...
]
wenn passt: weiter
sonst: ablehnen
3 Plan in feste Reihenfolge bringen

Vor jeder Antwort wird entschieden, ob Quellen gesucht, gerechnet oder beides gebraucht wird. 

plan = ["Wissen suchen"]

wenn frage enthält Zahl:
  plan += "Rechner nutzen"

plan += "Antwort schreiben"
4 Nur mit Beleg antworten

Ohne Treffer aus der Wissensbasis gibt es keine Sachantwort und keinen geratenen Leistungsanspruch. 

treffer = suche(frage)

wenn treffer leer:
  "keine passende Quelle"
sonst:
  antwort_mit(treffer.dok_id)
5 Antwort vor Ausgabe prüfen

Die finale Nachricht muss lesbar, vollständig und auf die gefundenen Quellen zurückführbar sein. 

prüfe(antwort):
  hat_text?
  nennt_quelle?
  enthält_tool_ergebnis?

wenn Prüfung fehlschlägt:
  Fallback ausgeben
Frage
→
Quelle oder Tool-Ergebnis
→
Antwort oder sichtbare Ablehnung

08 · Nächste Schritte

Wichtigste Änderungen für Production

Security

  • Authentication & Authorization
  • Rate Limiting & Input-Validation
  • Schutz vor Prompt Injection

RAG

  • FAISS → eher PostgreSQL mit pgvector
  • Hybrid Search + Reranking
  • Dokument-/Index-Versionierung

Agent

  • Persistenter State & Checkpoints
  • Timeouts, Retries & Fallbacks
  • Begrenzung von Agent-Schritten

LLM / Ollama

  • Evtl. Nutzung von Cloud-hosted LLMs
  • Monitoring von GPU, Latenz & Auslastung
  • Skalierung und Fallback-Modell

Observability

  • OpenTelemetry + Phoenix
  • Tracing von Agent, RAG und LLM
  • Metrics & Alerting ergänzen

Qualität

  • RAG-/LLM- und Tool-Evaluation via Unittests
  • Regressionstests
  • Evtl. User Feedback zu Antwortqualität
